# DH116S SDK 第一版接口

本文只说明第一版公共接口。每个接口按“作用、调用方式、返回值、说明”介绍，方便使用者直接查阅。CAN 帧、厂家 SDK、线程、重试和反馈匹配属于内部实现，见 [`cpp_v1_implementation_plan.md`](cpp_v1_implementation_plan.md)。

## 1. 第一版范围

第一版提供 Linux CAN FD 下 DH116S 六个主动通道的基本控制：连接、使能、失能、停止、回零、位置控制、速度和电流设置、力矩到位模式设置、状态读取。

第一版暂不提供设备信息、通道信息、故障清除、力控、阻抗、轨迹规划、手势和 ROS 2 专用接口。Python 与 ROS 2 适配层以后只复用这里的接口语义。

## 2. 通用约定

### 2.1 六轴顺序

所有六轴数组使用同一顺序：

| 数组下标 | 通道 ID | 通道 |
| ---: | ---: | --- |
| 0 | 1 | 拇指侧摆 |
| 1 | 2 | 拇指屈伸 |
| 2 | 3 | 食指屈伸 |
| 3 | 4 | 中指屈伸 |
| 4 | 5 | 无名指屈伸 |
| 5 | 6 | 小指屈伸 |

单轴接口使用 ID `1` 到 `6`。厂家使用的广播 ID `0` 不暴露给用户。

### 2.2 单位

| 数据 | 单位 |
| --- | --- |
| 目标位置、反馈位置 | 厂家行程当量，`0` 到 `10000` |
| 目标速度、反馈速度 | 厂家行程当量/秒 |
| 电流上限、反馈电流 | 厂家千分比值 |

位置是绝对目标值，不是相对位移，也不直接表示角度。

### 2.3 返回值

第一版不使用异常。可能失败的接口统一返回 `bool`，并记录可读日志：

- `true` 表示该接口定义的成功条件满足；
- `false` 表示参数、厂家调用、发送或必要反馈确认失败。

`bool` 的具体含义按接口说明理解。特别是，发送成功不等于设备已经运动或到位。

## 3. 公共接口

```cpp
class Hand {
public:
    bool connect(const std::string& can_name, int node_id);
    void disconnect();
    bool is_connected() const;

    bool enable();
    bool disable();
    bool stop();
    bool home();

    bool set_positions(const std::array<int, 6>& positions);
    bool set_position(int id, int position);
    bool set_speed(int speed);
    bool set_current_limit(int current);
    bool set_torque_reached_mode(bool stop_on_reached);

    HandState get_state() const;
};
```

控制接口由同一个调用线程顺序调用。用户不需要管理厂家 SDK、CAN socket 或接收线程。

当前 C++ 实现与 ARM 部署、demo 用法见 [README](../README.md)。普通操作建议由同一个用户线程顺序调用；SDK 内部统一转交专属控制线程。另一用户线程可通过 stop、disable、disconnect 取消操作等待。

## 4. 连接管理

### `connect(can_name, node_id)`

**作用**

连接指定的 CAN FD 接口和节点，初始化厂家 SDK，并建立必要的反馈通道。

**调用方式**

```cpp
bool ok = hand.connect("can0", 1);
```

**返回值**

- `true`：通信初始化成功，设备符合六轴 DH116S 要求，必要反馈可以接收；
- `false`：接口、节点、厂家初始化或反馈建立失败。

**说明**

初始化和反馈配置两个阶段各固定最多尝试 30 次，包含第一次；不对外提供重试次数参数。随后检查遗留急停：存在急停时先确认六轴失能且停止，再撤销急停并通过新反馈确认六轴退出急停、保持失能和停止且无报警。失能和撤销阶段各最多尝试 30 次，每次等待反馈最多 500 ms；失败则连接返回 false。连接可能发送失能和撤销急停命令，不是纯只读操作，但不会自动使能或回零。CAN FD 接口必须由主机预先配置并启用，SDK 不修改主机网络配置。

### `disconnect()`

**作用**

关闭 SDK、接收线程和 CAN socket，释放本地资源。

**返回值**

无返回值，重复调用安全。

**说明**

断开不会自动停止或失能设备。需要停机时，先调用 `stop()` 或 `disable()`。

### `is_connected()`

**作用**

查询本地连接状态。

**返回值**

`true` 表示 SDK 当前持有连接资源，`false` 表示尚未连接或已经断开。它不表示设备无报警或反馈一定新鲜。

## 5. 基本动作

### `enable()`

**作用**

使能六个主动通道，并确认设备反馈中的六轴使能状态。

**返回值**

`true` 表示六轴都已由新的设备反馈确认使能；`false` 表示命令发送失败或未确认全部使能。

**说明**

已全部使能时重复调用仍返回 `true`。使能不自动回零、不设置目标位置。部分轴使能不算成功，具体状态由 `get_state()` 查看。

### `disable()`

**作用**

取消本地待执行运动，失能六个主动通道，并确认设备反馈中的六轴失能状态。

**返回值**

`true` 表示六轴都已由新的设备反馈确认失能；`false` 表示命令发送失败或未确认全部失能。

**说明**

失能不清除报警、不保证手指张开，也不自动断开连接。

### `stop()`

**作用**

取消本地待执行的位置和回零等待，停止六个主动通道，并确认设备已停止。

**返回值**

`true` 表示六轴都已由新的反馈确认零速且不再运行；`false` 表示停止发送失败或停止状态未确认。

**说明**

`stop()` 保留使能状态，不等同于 `disable()`。底层软件急停可能保持；再次运动前应先失能、断开，再调用 `connect()` 重新初始化以检查并解除遗留急停，之后重新设置参数、使能和回零。

### `home()`

**作用**

执行六轴回零，并等待本次回零完成。

首次及重试均使用 `home_motors(0)` 整手回零。只要还有轴未观察到启动，就约每秒整手补发，最多 30 次（含首次）；不进行单轴补发。整手重试可能重新触发其他轴。六轴都观察到启动后只等待完成，总等待期限为 60 秒。

**返回值**

`true` 表示六轴都确认完成本次回零；`false` 表示回零未完成、反馈中断、设备报警或操作被停止/断开。

**说明**

调用需要已连接且控制队列可接受请求；接口不自动使能。下发回零命令前不检查反馈健康、使能或停止状态，由调用方安排设备状态。下发后仍检查反馈有效、无报警和六轴使能，并等待本次六轴回零完成；检查失败返回 false 不代表已物理停止。回零完成后恢复位置控制模式。回零是厂家专用动作，不等同于发送目标位置 `0`。

## 6. 位置和参数

### `set_positions(positions)`

**作用**

一次设置六轴目标位置，并触发一次整手运动命令。

**返回值**

`true` 表示输入合法、厂家调用成功且发送层接受命令；`false` 表示输入、厂家调用或发送失败。

**说明**

不等待设备运动，不确认到位，不自动重试。数组按固定六轴顺序传入，每个值必须在 `0` 到 `10000`。

### `set_position(id, position)`

**作用**

设置一个通道的目标位置，并触发该通道的运动命令。

**返回值**

`true` 表示 ID、位置合法，厂家调用和发送成功；`false` 表示参数、厂家调用或发送失败。

**说明**

`id` 必须在 `1` 到 `6`，位置必须在 `0` 到 `10000`。不等待到位，不自动重试，不改变其他轴目标。

### `set_speed(speed)`

**作用**

设置六个通道统一使用的位置运动速度。

**返回值**

`true` 表示输入合法且厂家设置调用成功；`false` 表示输入或厂家设置失败。

**说明**

返回 `true` 不表示设备已通过总线确认配置。实际运动速度从 `get_state()` 读取。

### `set_current_limit(current)`

**作用**

设置六个通道统一使用的电流上限。

**返回值**

`true` 表示输入合法且厂家设置调用成功；`false` 表示输入或厂家设置失败。

**说明**

单位是厂家千分比值，不是毫安或精确力矩。实际运行电流从 `get_state()` 读取。

### `set_torque_reached_mode(stop_on_reached)`

**作用**

设置力矩到位后的行为。

**参数**

- `true`：力矩到位后停止；
- `false`：力矩到位后保持。

**返回值**

`true` 表示厂家配置调用成功；`false` 表示配置失败。

**说明**

这个接口设置行为模式，不表示当前已经触发力矩到位。当前触发状态由 `get_state().torque_reached` 表示。

## 7. 状态读取

### `get_state()`

**作用**

读取接收线程保存的最新设备反馈快照。

**返回值**

```cpp
struct HandState {
    std::array<int, 6> positions;
    std::array<int, 6> velocities;
    std::array<int, 6> currents;
    std::array<bool, 6> enabled;
    std::array<bool, 6> homed;
    std::array<bool, 6> torque_reached;
    std::array<int, 6> fault_codes;
    bool feedback_valid;
};
```

**说明**

该接口不发送 CAN 查询，也不等待下一帧。`feedback_valid` 表示必要反馈最近仍有效，不表示设备无报警、已使能、已回零或运动成功。反馈过期时仍返回最后缓存，便于诊断。

## 8. 建议实现顺序

1. 定义六轴顺序、单位、参数范围和 `HandState`。
2. 完成 CAN FD 连接、接收、断开和反馈有效标志。
3. 完成 `get_state()`，验证位置、速度、电流、状态位和报警映射。
4. 完成 `enable()`、`disable()`、`stop()`，验证返回值只表示相应设备状态已确认。
5. 完成 `set_position()`、`set_positions()`，验证轴顺序、目标值和发送失败返回。
6. 完成 `home()`，验证本次回零完成后恢复位置模式。
7. 完成速度、电流和力矩到位模式设置。
8. 在 ARM64 目标机完成基本实机验证后，再实现 Python 和 ROS 2 适配。

## 9. 第一版验收点

- 连接、重复断开和线程/socket/SDK 资源释放正常。
- `get_state()` 的六轴顺序、单位和反馈有效标志正确。
- `enable()`、`disable()`、`stop()`、`home()` 只有在设备反馈满足条件时返回 `true`。
- `set_positions()` 和 `set_position()` 的 `true` 只表示发送流程成功，不表示设备到位。
- 设备报警、反馈过期和发送失败不会被伪装成成功。
- 断开不会隐式停止或失能设备。
