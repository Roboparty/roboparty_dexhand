# DH116S SDK 第一版接口讨论总结

本文记录目前讨论确定的接口范围和大致行为，作为第一版实现依据。函数签名、返回类型和默认参数尚未最终确定；本文不表示相关功能已经实现或完成实机验证。此前 `cpp_api_scope.md` 中与本文冲突的接口范围，以本文为准。

## 1. 第一版目标

提供最简单、可用的 DH116S 六通道控制 SDK：

- C++ 实现核心，在厂家 LHandProLib 上封装通信、初始化、控制和反馈。
- Python 绑定 C++ 核心，接口含义、单位和错误语义保持一致。
- 核心 SDK 独立使用，不依赖 ROS 2；ROS 2 后续作为独立适配层。
- 第一版以 Linux CAN FD 为目标，支持多只手分别连接和控制。
- 不提供 `get_info()`、`get_joint_info()`、`clear_faults()`。
- 告警信息由 `get_state()` 返回，暂不提供自动清除、恢复等告警处理流程。
- 连接失败、发送失败、参数错误、超时等调用错误仍需明确返回。

## 2. 控制通道与单位

固定控制六个主动通道，整手数组长度为 6，顺序如下：

| 单通道 ID | 名称 |
| --- | --- |
| 1 | 拇指侧摆 |
| 2 | 拇指屈伸 |
| 3 | 食指屈伸 |
| 4 | 中指屈伸 |
| 5 | 无名指屈伸 |
| 6 | 小指屈伸 |

单通道接口使用 ID 1～6；整手操作使用专门的接口，不额外暴露厂家 ID 0 的广播约定。数组第一个元素对应通道 1。

| 数据 | 公共接口单位 |
| --- | --- |
| 目标位置、反馈位置 | 厂家行程当量，0～10000 |
| 运动速度、反馈速度 | 厂家 SDK 的当量/秒 |
| 电流上限、反馈电流 | 厂家千分比值 |

位置 0 表示起始位，10000 表示满行程，5000 表示全行程 50% 处的绝对位置。它不是本次运动完成进度，也不是相对移动量。不做角度换算，不承诺与关节角度线性对应。

公共速度单位采用厂家 SDK 的当量/秒，不能与协议帧中的原始速度整数直接混用。电流千分比不能当作 mA、N 或精确力矩值。

## 3. 对外接口

下表中的参数是语义示意，不是最终 C++ 或 Python 签名。

| 接口 | 大致职责 |
| --- | --- |
| `connect(can, node_id, retry_count = 30)` | 分阶段重试厂家初始化及反馈配置检查；固定 50 Hz，全部通过后建立可用连接 |
| `disconnect()` | 无参数地关闭 SDK 和通信，回收线程；可重复调用，不自动停止或失能，不套连接重试 |
| `enable()` | 无参数，固定最多尝试 30 次；返回最后有效反馈的六轴使能数组，全部使能即提前返回 |
| `disable()` | 无参数，固定最多尝试 30 次；返回六轴使能状态数组，全部为 false 表示已失能；反馈过期时仍尝试下发 |
| `home()` | 无参数，整手触发回零并按轴补发；返回六轴本次回零完成状态，完整确认后才成功 |
| `set_positions(values)` | 直接按六轴顺序调用厂家目标和运动接口，不做设备状态检查、不等待到位、不保证执行成功 |
| `set_position(id, value)` | 只检查 ID 和位置输入，直接调用单轴厂家接口；不检查设备状态、不等待、不保证执行成功 |
| `set_speed(value)` / `get_speed()` | 设置并读取六通道目标速度；设置固定重试 30 次，读取的是厂家缓存，不是设备 ACK |
| `set_current_limit(value)` / `get_current_limit()` | 设置并读取六通道目标电流上限；设置固定重试 30 次，读取的是厂家缓存，不是设备 ACK |
| `set_torque_reached_mode(mode)` / `get_torque_reached_mode()` | 用 0/1 设置并读取力矩到位行为；1 为停止、0 为保持，设置最多重试 30 次 |
| `get_state()` | 读取最近反馈，包括六通道位置、速度、电流、状态和告警 |
| `stop()` | 无参数，固定最多尝试 30 次；返回六轴停止确认状态，全部为 true 表示已确认停止 |

`set_positions()` 和 `set_position()` 内部完成厂家设置目标、触发运动的流程，用户不需要额外调用 `move_motors()`。这两个接口只检查输入数量、通道 ID 和位置范围，不在 SDK 层检查连接、使能、回零、反馈新鲜度或设备到位状态，也不检查厂家返回结果，不提供重试和设备确认。调用者负责保证前置状态，设备是否接受和执行由后续 `get_state()` 反馈判断。

速度和电流上限第一版先统一设置六通道，不增加逐轴配置。参数的具体生效时机需在实现时明确，不能仅修改厂家缓存却向用户报告设备已经生效。

### set_speed() / get_speed() 约定（已确认）

`set_speed(value)` 的单位是厂家行程当量/秒，输入合法后最多尝试 30 次。每次在同一厂家控制线程调用 `set_position_velocity(0, value)` 和 `apply_motion_params()`，再通过六次 `get_position_velocity(id, &value)` 检查六轴厂家缓存是否一致；一致后返回。30 次后仍无法确认缓存一致时抛异常。

`get_speed()` 返回 `std::array<int, 6>`，表示六个轴当前在厂家 SDK 中保存的目标速度。这个读取不是设备对速度参数的总线确认，也不是电机当前实际速度。设备运动时的实际速度通过 `get_state().velocities` 读取。即使 `set_speed()` 成功，也不保证设备已经应用该速度。

### enable() 返回约定（已确认）

C++ 返回 `std::array<bool, 6>`，按固定通道顺序表示实际使能状态，true 为使能、false 为未使能。内部整手下发、逐轴确认，最多尝试 30 次（包含第一次），不向用户开放次数参数，也不沿用 connect 的可配置次数。

新鲜反馈已显示六轴使能时可直接返回；否则执行使能准备和重试，收到新的有效反馈且六轴全部使能时立即返回。次数耗尽仍未全部使能，但有本次操作期间的新反馈且仍未过期时，正常返回最后一份数组，允许部分 false。调用方需检查数组，而不是把正常返回等同于全部使能。

未连接、反馈缺失或过期、操作被取消等情况下抛异常，具体异常类型待统一。不能以默认全 false 表示未知状态。使能准备阶段调用失败也抛异常，不以状态数组掩盖错误。未全部使能不自动失能、清告警或断开；enable 不回零、不下发位置目标。

### disable() 返回约定（已确认）

C++ 入口为 `std::array<bool, 6> disable()`，无参数，固定最多尝试 30 次包含首次，不受 connect 的 retry_count 影响。数组与 enable 的含义一致：true 为仍使能，false 为已失能，全部失能应返回六个 false。

先取消待发运动、使能重试和回零等待，再整手调用厂家 set_enable(0, 0)，等待新反馈逐轴确认。新鲜反馈已确认全部失能时可直接返回。次数耗尽但有本次操作期间的新反馈且仍有效时，返回最后一份数组，允许部分 true。

反馈过期不阻止尝试发送失能，也不要求 stop 已成功。最终没有有效反馈时抛异常，不能返回全 false 冒充已失能；未连接或操作被取消同样抛异常。保留连接、不清告警，不强制重置 homed，回零状态仍以设备反馈为准。

### home() 返回和重试约定（已确认）

C++ 入口暂定为 `std::array<bool, 6> home()`，无参数。要求已连接、六轴已使能且没有其他运动；不自动调用 `enable()`。

首次调用厂家 `home_motors(0)` 广播触发六轴回零。此后每隔约 1 秒检查一次状态：已经观察到进入“回零运行”的轴不再重发；尚未观察到开始回零的轴，调用 `home_motors(id)` 对该轴补发。每轴最多 30 次，包含首次广播触发对应的一次。整个操作另有内部总超时，等待间隔和总超时时间待实测确定。

每个轴的完成条件是：本次调用期间先观察到回零运行，再观察到已回零、退出回零运行且零速。六轴全部完成后调用厂家 `set_control_mode(0, LCM_POSITION)` 恢复位置模式，返回六个 true。已有的旧 `homed=true` 不能单独作为本次回零完成依据。

回零过程中收到 stop、disable 或 disconnect 时取消等待并执行对应操作；超时或反馈中断时返回异常，不返回部分完成数组。取消等待不等于设备停止。回零不等于发送目标位置 0，不额外设置厂家回零电流，也不自动清除告警。

## 4. 连接内部流程与帧率检查

`connect()` 包含厂家初始化函数，用户无需另行初始化。入口已确定只接收 CAN 接口、节点 ID、重试次数，默认 30 次包含首次尝试。反馈固定为 50 Hz（20 ms），不开放频率和超时参数。

```text
阶段一，每次尝试：
  创建厂家实例，打开 CAN FD 通信
    → 注册发送回调，启动接收线程
    → 调用 initial(LCN_CANFD, node_id)，检查初始化结果
  失败则清理本次资源，间隔后重建并重试

阶段二，每次尝试：
  配置六轴反馈周期为 20 ms，并读回检查
    → 配置 0x50、0x5A，每个周期各上报一次
    → 重新统计新反馈，分别检查实际频率约为 50 Hz
  失败则保留已初始化的连接，间隔后重试本阶段

两阶段各最多尝试 retry_count 次
全部通过才返回连接成功；任一阶段次数耗尽则清理资源并返回失败
```

接收线程必须在厂家初始化前启动，因为初始化可能发送查询并等待设备应答。两个阶段分别计数，不对每个轴再嵌套相同次数重试。明显的输入参数错误直接返回，不重试。各次应答等待、配置检查有内部期限，重试间隔也在内部设置。

帧率配置和检查包括：

- CAN TPDO 基础周期：单位为 0.1 ms，设置为 200，即 20 ms；需设置六个索引 `0x201D/0x205D/0x209D/0x20DD/0x211D/0x215D` 的子索引 `0x14`。
- 两类反馈帧的发送间隔倍数均设为 1，每类各自为 50 Hz。
- 必要反馈类型：`0x50` 位置、速度、电流反馈，以及 `0x5A` 状态、告警反馈。
- 配置后分别检查两类帧是否到达及实际接收周期，不能将两类帧的数量相加当作单类反馈频率。
- 配置失败、必要反馈缺失或频率检查不通过时，重试整个第二阶段；次数耗尽才返回错误并清理连接资源。

统计窗口、允许偏差、单次等待期限和重试间隔需根据实测确定。设备反馈固定 50 Hz，不代表用户必须以 50 Hz 调用 `get_state()` 或发送位置。重试次数不等于总时间上限，厂家阻塞调用的时长也需验证。

`connect()` 不自动使能或回零，也不保证设备原来处于失能状态；实际状态以反馈为准。

### disconnect() 的内部流程（已确认）

入口为 `hand.disconnect()`，不需要参数。

```text
标记正在关闭，拒绝新的普通控制请求
  → 取消待执行请求、连接重试和操作等待
  → 等已进入的厂家调用返回
  → 调用厂家 close()，保留清理期间需要的回调和通信对象
  → 协调接收解码退出，等待接收线程结束
  → 销毁厂家实例、关闭 socket、释放回调并回收控制线程
  → 标记已断开、反馈无效，返回清理结果
```

- 已完全断开时直接成功；重复或并发请求不得重复释放资源。
- 不等待设备应答，不套 connect 的 30 次重试；CAN 已断线也执行本地清理。
- 清理顺序需协调厂家 close 与接收解码，资源不能在仍被线程或回调使用时销毁。
- 不自动发送 stop 或 disable。取消回零等待不代表设备停止回零，断开后设备可能继续执行最后收到的命令。
- 只有完成实际资源回收才报告清理成功；再次连接时重新创建实例并初始化。

## 5. 连接、使能、回零和停止的关系

| 操作 | 影响范围 |
| --- | --- |
| 连接 | 建立通信，允许读状态和发送控制命令 |
| 使能 | 开启电机驱动，使其具备执行运动的条件 |
| 回零 | 驱动电机执行硬件回零，建立或校正零点 |
| 停止 | 停下当前运动，不主动失能，不关闭通信 |
| 失能 | 关闭电机驱动，保留通信；不保证手指张开或机械松脱 |
| 断开 | 释放通信资源，不能保证设备停止或失能 |

典型首次控制流程：

```text
connect()
  → 配置速度、电流上限、力矩到位模式
  → enable()
  → home()
  → set_positions(...) / set_position(...)
```

先使能再回零，因为回零需要电机实际运动。`enable()` 不自动回零；`home()` 不等于发送目标位置 0。是否需要再次回零应结合设备实际回零状态判断。

需要停机并释放连接时，可以显式执行：

```text
stop() → disable() → disconnect()
```

停止后也可以继续保留连接和使能。恢复运动需处理厂家要求的恢复步骤，并使用新的目标，避免意外恢复旧动作。停止命令不承诺持续位置保持，其底层行为需实机确认。

## 6. 力矩到位模式（已确认）

对外直接使用整数模式，不额外定义枚举：

```cpp
set_torque_reached_mode(1);  // 安全电流开启，力矩到位停止，默认
set_torque_reached_mode(0);  // 安全电流关闭，力矩到位保持
int mode = get_torque_reached_mode();
```

| 模式 | 手册描述的行为 |
| --- | --- |
| 力矩到位停止 `Stop` | 力矩到位时停止当前运动，并限制输出电流 |
| 力矩到位保持 `Hold` | 力矩到位时持续保持设定电流；阻力减小时继续向目标位置运动 |

“保持”指保持电流输出，不是锁住当前位置。`set_current_limit()` 设置电流上限，本接口设置到位后的行为。到位停止模式是设备运动过程中的自动行为，与用户显式调用 `stop()` 是不同入口。

当前版本直接使用厂家 `set_safe_current_enable(0/1)` 和 `get_safe_current_enable()`。公共定义固定为：1 是安全电流开启和力矩到位停止，0 是安全电流关闭和力矩到位保持。设置最多重试 30 次，每次设置后读取厂家状态；读取的是配置状态，不是设备 ACK。默认模式为 1。

## 7. get_state() 的内容

拟返回以下数据，数组均按固定六通道顺序排列：

| 字段 | 含义 |
| --- | --- |
| `positions[6]` | 实际位置，行程当量 |
| `velocities[6]` | 实际速度，当量/秒 |
| `currents[6]` | 实际电流，千分比 |
| `enabled[6]` | 实际使能状态 |
| `homed[6]` | 回零状态 |
| `torque_reached[6]` | 力矩到位状态 |
| `fault_codes[6]` | 厂家告警码，不自动清除或恢复 |

`get_state()` 读取最近收到的反馈缓存，不因每次调用而重新查询设备。SDK 内部需跟踪必要反馈是否齐全及是否过期，不能将断线前缓存当成当前有效状态。

反馈有效性采用 `feedback_valid` 字段。缺帧或反馈过期时为 false，但 `get_state()` 仍返回最后缓存；它不表示无告警、已经到位或运动成功。调用者根据该字段决定是否使用缓存数值。

## 8. 实现前仍需确认的细节

- 安全电流模式在不同固件版本上的实际生效行为仍需实机验证。
- `stop()` 后设备的具体行为和恢复运动步骤。
- 反馈检查窗口、容差、内部单次等待期限、重试间隔和运行期间的过期阈值；连接反馈固定 50 Hz 已确定。
- `get_state()` 的过期阈值和反馈统计细节。
- 速度、电流参数的范围、默认值及下发生效时机。
- 各接口的返回类型、等待超时和取消方式。
